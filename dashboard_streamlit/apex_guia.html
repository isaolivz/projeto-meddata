Abrir o APEX e criar o app

Cinco passos, uma vez só — depois disso você só cria páginas e regiões.

1. No console da OCI, abra seu Autonomous Database → botão "Database Actions" → aba "Development" → ícone APEX. Isso abre o workspace já ligado ao mesmo banco que o Select AI usa hoje.
2. No APEX, vá em App Builder → Create → New Application, dê um nome (ex.: "MedData") e clique em Create Application. Isso cria uma app com uma Home page vazia.
3. Dentro da app, Create Page → Blank Page pra cada página que você for montar (uma por seção deste guia).
4. Dentro de uma página, Create Region — cada bloco deste guia (um gráfico, uma tabela, os KPIs) é uma region separada.
5. Toda region baseada em dado tem uma aba Source — é lá que você cola a query SQL de cada passo abaixo.

00a

Se aparecer "tabela ou visão não existe"

Erro real que apareceu no primeiro teste deste guia — melhor resolver logo no início, antes de bater em todas as 12 regions do guia.

ORA-00942: a tabela ou visão "WKSP_ALGUMACOISA"."FATO_INTERNACAO_V2" não existe. Isso acontece porque o workspace do APEX usa um schema próprio (geralmente vazio), diferente do schema ADMIN, onde os dados de verdade moram. Toda query deste guia já está escrita com o prefixo ADMIN. na frente de cada tabela por causa disso — mas antes de rodar a primeira, você precisa liberar o acesso uma única vez.

Passo único, feito uma vez: na tela Database Actions (a mesma de onde você abriu o APEX), clique em SQL em vez de "APEX" — isso abre um editor conectado como ADMIN. Cole e rode: 

-- Troque WKSP_ALGUMACOISA pelo nome real do schema que apareceu no SEU erro
GRANT SELECT ON ADMIN.FATO_INTERNACAO_V2 TO WKSP_ALGUMACOISA;
GRANT SELECT ON ADMIN.DIM_HOSPITAL_V2 TO WKSP_ALGUMACOISA;
GRANT SELECT ON ADMIN.DIM_MUNICIPIO_V2 TO WKSP_ALGUMACOISA;
GRANT SELECT ON ADMIN.DIM_TEMPO_V2 TO WKSP_ALGUMACOISA;
GRANT SELECT ON ADMIN.DIM_DIAGNOSTICO_V2 TO WKSP_ALGUMACOISA;
GRANT SELECT ON ADMIN.VW_ALERTAS_COLAPSO TO WKSP_ALGUMACOISA;
GRANT SELECT ON ADMIN.VW_MUNICIPIO_INTERNACOES TO WKSP_ALGUMACOISA;
GRANT SELECT ON ADMIN.VW_DIAGNOSTICO_SIMPLES TO WKSP_ALGUMACOISA;

O nome do seu schema aparece exatamente no texto do erro, entre aspas, antes do ponto (ex.: "WKSP_MEDDATA"). Depois de rodar isso uma vez, toda query com ADMIN. na frente do nome da tabela passa a funcionar normalmente.

Bônus: se o texto do seu SQL aparecer traduzido pro português de um jeito estranho ("SELECIONE", "ONDE", "UNIÃO TOTAL") dentro do editor do APEX, é o Chrome traduzindo a página automaticamente — desative em "..." → Traduzir → Nunca traduzir este site, pra não arriscar o código real ser alterado.
00b

Onde clicar — anatomia da tela

Quando você abre uma página no Page Designer (é assim que se chama a tela de edição), ela sempre tem 3 painéis. Ler essa tela é 80% do trabalho de aprender APEX.

1 · Rendering (esquerda)
A árvore da página: Regions, Items, Buttons, Dynamic Actions. É aqui que você cria coisas novas (botão direito → Create) e navega entre o que já existe.
2 · Canvas (meio)
Uma prévia de como a página vai ficar. Clicar numa region aqui seleciona ela — mesmo efeito de clicar nela na árvore da esquerda.
3 · Property Editor (direita)
Mostra as propriedades de quem estiver selecionado. É aqui que você escreve o Título, escolhe o Type, e — rolando pra baixo — encontra a seção Source com o campo SQL Query.
Receita genérica — vale pra toda region deste guia
  1. Na árvore Rendering (painel 1), clique com o botão direito em Regions → Create Region.
  2. A region nova aparece selecionada e o Property Editor (painel 3) abre nela. Primeiro campo, Title — dê um nome (ex.: "KPIs", "Ranking de hospitais").
  3. Logo abaixo, o campo Type — escolha o tipo: Cards, Chart, Interactive Report, Map Region... A tela muda de acordo com o que você escolher.
  4. Role o Property Editor pra baixo até achar a seção Source. No campo SQL Query, apague o texto de exemplo e cole a query deste guia.
  5. Configure o que for específico do tipo escolhido — veja a tabela logo abaixo, porque colar o SQL sozinho não é suficiente pra gráfico e mapa.
  6. No topo da tela, clique no ícone de disquete (Save), depois no botão verde ▶ (Run Page) — abre uma aba nova já com a página funcionando.
O que fazer depois de colar o SQL, por tipo de region

Essa é a resposta pra "colando a query já sai o gráfico?" — depende do tipo: Cards e Interactive Report praticamente só precisam do SQL; Chart e Map Region pedem um passo extra pra dizer qual coluna é o quê.

Tipo de regionDepois de colar o SQL...
Cards No Property Editor, procure Column Mapping e diga qual coluna é o Title e qual é o Text/Badge — no seu caso, sempre TITULO e VALOR.
Chart Na árvore (painel 1), a region ganha um filho chamado Series — clique nele e, no Property Editor, defina Label Column e Value Column com os nomes das colunas do seu SELECT. O tipo do desenho (barra/linha/pizza) fica no campo Type da region principal, seção Appearance.
Interactive Report Nada — ele já desenha a tabela com as colunas que vierem do SELECT.
Map Region Na árvore, botão direito em Map Layers (dentro da region) → Create Map Layer. No Property Editor dessa camada, em Location, escolha "Latitude/Longitude Columns" e selecione as colunas certas.
Function Body returning SQL Query
(usado no Pergunte aos Dados)		 Antes de colar, na seção Source mude o campo Location de "Local Database" pra "Function Body returning SQL Query" — só depois desse clique o campo vira um editor de PL/SQL onde cabe o bloco inteiro (DECLARE...END;).
00c

Menu lateral (o "sidebar")

Boa notícia: diferente do Streamlit (onde o menu lateral nasce dos arquivos numerados em pages/), no APEX ele já vem pronto. Você só precisa garantir que cada página está cadastrada nele.

Pra conferir ou editar: dentro da sua app, vá em Shared Components (ícone de peças de quebra-cabeça, ou no menu superior) → seção Navigation → Navigation Menu. Ali aparece uma entrada por página — dá pra arrastar pra reordenar (mesma ideia dos prefixos 1_, 2_... do Streamlit), renomear, ou clicar em Create Entry pra adicionar uma página que não apareceu sozinha.

Ao criar uma página pelo assistente, se aparecer uma pergunta do tipo "Add Page to Navigation Menu?", deixe marcado "Yes" — é isso que faz ela aparecer no menu sem precisar voltar em Shared Components depois.

02

Monitoramento

Equivalente a pages/1_Monitoramento.py. Tudo aqui usa a view VW_ALERTAS_COLAPSO, que já vem com ocupação e nível de alerta calculados por hospital.

Antes de começar — um dado real com problema: cerca de 62 hospitais (de 1.466) têm LEITOS_TOTAIS inflado por um bug de geração de dado (confirmado direto no banco: um hospital aparece com 1.804 leitos). Toda query abaixo que soma leitos já inclui WHERE leitos_totais < 500 como filtro defensivo — isso é uma limitação de dado conhecida e documentada, não um erro seu. Se o professor perguntar, é um ponto a favor citar que vocês identificaram e trataram isso conscientemente.
KPIs (internações, ocupação, leitos livres, alertas) Cards

Cada linha do resultado vira um card. No assistente da region, mapeie TITULO como título e VALOR como o texto do card.

-- Ocupacao usa SOMA/SOMA, nao media simples das taxas -- ver nota abaixo
SELECT 'Internações no total' AS titulo, TO_CHAR(COUNT(*)) AS valor
FROM ADMIN.FATO_INTERNACAO_V2
UNION ALL
SELECT 'Ocupação média da rede',
       TO_CHAR(ROUND(SUM(leitos_ocupados) / SUM(leitos_totais) * 100, 1)) || '%'
FROM ADMIN.VW_ALERTAS_COLAPSO WHERE leitos_totais < 500
UNION ALL
SELECT 'Leitos disponíveis',
       TO_CHAR(SUM(leitos_totais - leitos_ocupados))
FROM ADMIN.VW_ALERTAS_COLAPSO WHERE leitos_totais < 500
UNION ALL
SELECT 'Hospitais em alerta crítico', TO_CHAR(COUNT(*))
FROM ADMIN.VW_ALERTAS_COLAPSO
WHERE nivel_alerta IN ('Vermelho','Laranja') AND leitos_totais < 500
Importante: some SUM(leitos_ocupados)/SUM(leitos_totais), nunca AVG(taxa_ocupacao) direto — essa foi uma inconsistência real que já apareceu no projeto (dava 6% numa conta e 11-12% na outra, pro mesmo período). A ponderada é a correta.
Ranking dos hospitais mais críticos Chart · Bar

Barra horizontal. No assistente: Label = HOSPITAL, Value = TAXA_OCUPACAO.

SELECT nome_hospital || ' (' || nome_municipio_hospital || ')' AS hospital,
       taxa_ocupacao,
       nivel_alerta
FROM ADMIN.VW_ALERTAS_COLAPSO
WHERE leitos_totais < 500
ORDER BY taxa_ocupacao DESC
FETCH FIRST 10 ROWS ONLY

Opcional (se sobrar tempo): use NIVEL_ALERTA como "Series By" pra colorir automaticamente por status.

Tabela detalhada de hospitais críticos Interactive Report

A mesma view, sem limite de linhas — o Interactive Report já dá busca e ordenação de graça.

SELECT id_hospital, nome_hospital, nome_municipio_hospital,
       leitos_totais, leitos_ocupados, taxa_ocupacao, nivel_alerta
FROM ADMIN.VW_ALERTAS_COLAPSO
WHERE leitos_totais < 500
ORDER BY taxa_ocupacao DESC

Visão Geral

Equivalente a pages/2_Visao_Geral.py. Mesma técnica do Monitoramento — só muda a query de cada region.

KPIs de volume Cards
SELECT 'Total de internações' AS titulo, TO_CHAR(COUNT(*)) AS valor FROM ADMIN.FATO_INTERNACAO_V2
UNION ALL
SELECT 'Hospitais atendendo', TO_CHAR(COUNT(DISTINCT id_hospital)) FROM ADMIN.FATO_INTERNACAO_V2
UNION ALL

UNION ALL
SELECT 'Leitos totais', TO_CHAR(SUM(leitos_totais)) FROM ADMIN.DIM_HOSPITAL_V2 WHERE leitos_totais < 500
Internações por período Chart · Line

Label = ANO_MES, Value = INTERNACOES.

SELECT t.ano_mes, COUNT(*) AS internacoes
FROM ADMIN.FATO_INTERNACAO_V2 f
JOIN ADMIN.DIM_TEMPO_V2 t ON t.tempo_id = f.tempo_id
GROUP BY t.ano_mes
ORDER BY t.ano_mes
Ranking de municípios Chart · Bar
SELECT nome_municipio, SUM(total_internacoes) AS internacoes
FROM ADMIN.VW_MUNICIPIO_INTERNACOES
GROUP BY nome_municipio
ORDER BY internacoes DESC
FETCH FIRST 10 ROWS ONLY
Top 10 diagnósticos Chart · Bar

O APEX não tem treemap nativo como o Plotly — uma barra horizontal cobre o mesmo recado (ranking), só sem a ideia de "proporção do todo". 

SELECT descricao_cid, SUM(total_internacoes) AS internacoes
FROM ADMIN.VW_DIAGNOSTICO_SIMPLES
GROUP BY descricao_cid
ORDER BY internacoes DESC
FETCH FIRST 10 ROWS ONLY
Pacientes que viajaram Chart · Pie

Rode um SELECT DISTINCT paciente_viajou FROM ADMIN.FATO_INTERNACAO_V2 antes, pra confirmar se os valores são texto ('True'/'False') como no CSV local.

SELECT paciente_viajou, COUNT(*) AS internacoes
FROM ADMIN.FATO_INTERNACAO_V2
GROUP BY paciente_viajou
Mapa geográfico Map Region (Point Map) · opcional

Mapeie LATITUDE/LONGITUDE como coordenadas e INTERNACOES como tamanho do ponto.

SELECT m.nome_municipio, m.latitude, m.longitude, COUNT(*) AS internacoes
FROM ADMIN.FATO_INTERNACAO_V2 f
JOIN ADMIN.DIM_MUNICIPIO_V2 m ON m.codigo_municipio = f.codigo_municipio_paciente
GROUP BY m.nome_municipio, m.latitude, m.longitude
Evolução mensal dos hospitais de maior volume opcional — simplificado

O APEX não tem um equivalente direto ao gráfico animado do Plotly (animation_frame). Em vez de tentar recriar a animação, mostre um ranking simples do último mês — mais rápido de construir e comunica quase a mesma coisa: 

SELECT f.id_hospital, f.nome_municipio_hospital, COUNT(*) AS internacoes
FROM ADMIN.FATO_INTERNACAO_V2 f
JOIN ADMIN.DIM_TEMPO_V2 t ON t.tempo_id = f.tempo_id
WHERE t.ano_mes = (SELECT MAX(ano_mes) FROM ADMIN.DIM_TEMPO_V2)
GROUP BY f.id_hospital, f.nome_municipio_hospital
ORDER BY internacoes DESC
FETCH FIRST 8 ROWS ONLY
04

Pergunte aos Dados

Essa é a parte mais legal de mostrar pro professor: o mesmo DBMS_CLOUD_AI.GENERATE que o Streamlit chama em Python dá pra chamar direto de dentro de uma region do APEX — sem nenhum código Python no meio. Deixe essa pra quando já estiver confortável com o APEX (dia 3).

Campo de pergunta + botão Page Item + Button

Crie um Page Item de texto chamado P1_PERGUNTA (Text Field) e um botão "Perguntar" do tipo Submit.

Região de resultado com SQL dinâmico Interactive Report

Crie uma region "Interactive Report". Na aba Source → Location, escolha "Function Body returning SQL Query" (não "Local Database" — é esse modo especial que deixa o APEX executar uma query que só existe em tempo de execução). Cole: 

-- Mesma logica do core/db.py do projeto Streamlit, so que em PL/SQL
DECLARE
  l_sql CLOB;
BEGIN
  IF :P1_PERGUNTA IS NULL THEN
    RETURN q'[SELECT 'Digite uma pergunta acima e clique em Perguntar' AS mensagem FROM dual]';
  END IF;

  l_sql := DBMS_CLOUD_AI.GENERATE(
    prompt       => :P1_PERGUNTA,
    profile_name => 'MEDDATA_PRECISAO',
    action       => 'showsql'
  );

  -- remove cercas de markdown (```sql ... ```) e ; final, se vierem
  l_sql := REGEXP_REPLACE(l_sql, '```[[:alnum:]]*', '');
  l_sql := RTRIM(TRIM(l_sql), ';');

  RETURN l_sql;
END;

Depois, crie uma Dynamic Action no clique do botão: True Action = Refresh, Selection Type = Region, Region = essa que você acabou de criar.

Explicação em português (bônus) Display Item + Process

Crie um item P1_EXPLICACAO (Display Only) e, na mesma Dynamic Action do botão, adicione uma ação "Execute Server-side Code" antes do Refresh: 

:P1_EXPLICACAO := DBMS_CLOUD_AI.GENERATE(
  prompt       => :P1_PERGUNTA,
  profile_name => 'MEDDATA_PRECISAO',
  action       => 'chat'
);

Marque P1_EXPLICACAO como "Page Items to Return" nessa ação, senão o valor não volta pra tela.

Mesmas limitações de sempre: o Select AI não é determinístico (a mesma pergunta pode gerar SQL diferente em outra tentativa) e perguntas de distância/geolocalização ainda são o ponto mais frágil. Isso já está documentado no relatório "Raio-X do MedData" — vale citar pro professor que é uma limitação conhecida do modelo, não um bug escondido.
05

O que fica de fora (e por quê)

Chat MedData não migra pro APEX: ele depende de RAG em Python (LangChain + ChromaDB + embeddings locais), e o APEX não roda Python. Pra existir lá dentro, precisaria expor essa lógica como uma API externa chamada via REST — trabalho grande demais pro prazo que você tem. Vale deixar isso explícito na apresentação: o Chat continua só no Streamlit, por uma limitação técnica real do APEX, não por falta de tempo.
